# ThyncSpace backend review — 12 October 2026

Organization, history and trash operations use owner-scoped queries. Recovery
creates a new private note in a transaction and consumes a trash tombstone once.
History retains five prior snapshots atomically with content. Version names and
content review are owner-only. Permanent deletion requires explicit confirmation
and a trashed owner record; active notes cannot pass that endpoint.

Content writes require an expected content revision. Stale private updates and
first-share snapshots return 409; missing revisions return 428. REST cannot
replace shared content. Title-only changes remain separate from content revisions.
Bulk import now captures committed records correctly with the installed MongoDB
driver and retains validated relative source paths.

Live updates are validated against an isolated Yjs document before mutation.
Raster admission, size/geometry limits, no-store headers, malformed upgrade targets
and private response projection are covered. Durable store receipts hash canonical
materialized state, including deletions, rather than replica-specific binary data.
Receipts describe the snapshot written, not edits that arrived during the write.

## Verification

- npm run check: lint, types, build and 40 unit/security tests pass.
- npm run test:integration: 15 tests/subtests pass on a disposable MongoDB 8.0.16
  replica set. They cover imports, concurrent revision conflicts, bounded history,
  version privacy/naming, explicit trash deletion, transaction rollback, first-share
  handoff and concurrent recovery. New cases cover template privacy, UTF-8 storage
  totals, atomic bulk moves, literal tag merges and account-owned workspace settings.
- The frontend live suite uses this server with real WebSocket and database traffic
  to verify durable receipts and live draft replay after page closure.
- Full npm audit reports zero vulnerabilities.

The database tests run without Docker and never read the application .env. The
first run downloads the test MongoDB binary. Temporary databases are stopped and
removed after each run. Production IAM, OAuth credentials, backup restoration,
load capacity and multi-instance consistency remain outside local verification.
The supported deployment has one authoritative collaboration process. No production
data, deployment, npm registry or remote Git repository was changed.

Follow-up: awareness identity is server-authenticated, connection/session ownership is enforced, cursor fields are bounded, and unexpected fields are removed. The added unit regression covers forged identity, another client ID, and malformed positions.

Workspace review: API schemas reject operator-shaped values, unknown filters, invalid date ranges, oversized lists and inaccessible note IDs. Concurrent pins retain both changes; saved views and recent visits do not cross account boundaries. IDs normalize case before deduplication.

Archive follow-up: archive flags are owner-only organization. Mixed-owner bulk requests roll back, malformed flags are rejected, and archiving preserves content and existing collaborators. All 40 unit tests and 14 integration tests/subtests pass.

Session review: collaboration tokens previously survived ordinary logout. Tokens now bind to a device ledger, logout and remote revocation close matching sockets, and stale cookie requests cannot recreate revoked sessions. Startup waits for unique indexes. Forty unit tests and 15 integration tests/subtests pass; the real two-account browser suite confirms targeted revocation leaves the other account connected.
